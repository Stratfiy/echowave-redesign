---
title: "Connect with Telephony"
description: "Hook up a carrier so your agent makes and takes real phone calls, not just browser tests."
---

Everything so far has worked in the browser. To put the agent on an actual phone
line you need a carrier account, and Decibyl needs the credentials to it.

This page uses **Twilio**, because it is the quickest to get running: you can
buy a number and place a test call on trial credit within a few minutes.
[Plivo](/integrations/telephony/plivo), [Vonage](/integrations/telephony/vonage),
[Telnyx](/integrations/telephony/telnyx) and
[Cloudonix](/integrations/telephony/cloudonix) work the same way with different
credentials — or skip the carrier account entirely and have us
[provision a number for you](/integrations/telephony/managed-numbers).

<Note>
**Calling Indian numbers?** Read
[Before You Start](/getting-started/prerequisites#if-you-are-calling-indian-numbers)
first. KYC and DLT registration take real time to clear and cannot be rushed on
the day you want to launch.
</Note>

<Steps>

<Step title="Buy a number at Twilio">

Sign up at [twilio.com](https://www.twilio.com). On the dashboard, go to
**Phone Numbers → Buy a number** and take any number. Trial credit covers it.

</Step>

<Step title="Copy your Account SID and Auth Token">

Both are on the Twilio console home page. The Auth Token is a credential with
full access to your Twilio account — treat it the way you would a password.

</Step>

<Step title="Create the configuration in Decibyl">

Open **Telephony**, click **Add Configuration**, and pick **Twilio**. Name it
something you will recognise later — the agent's name works well. Paste the
Account SID and Auth Token.

<Screenshot
  src="telephony-add-configuration.png"
  alt="The Add Configuration dialog in Decibyl with Twilio selected and the SID and token fields"
  caption="One configuration per carrier account. Name it after what it is for."
  shot="The Telephony → Add Configuration dialog with provider Twilio selected, name filled in, and the credential fields present but redacted."
/>

<Warning>
Switch on **Set as default for outbound calls**. Without a default, an
[API Trigger](/getting-started/trigger-calls-from-your-backend) returns
`400: Telephony provider not configured for this organization` even though the
configuration exists and is perfectly valid.
</Warning>

Leave answering-machine detection off for a first setup, and click **Create**.

</Step>

<Step title="Add your number">

With the configuration created, open its phone numbers and add the number you
bought. Paste it exactly as Twilio shows it, in E.164 form (`+14155550100`), and
set the country to match.

<Screenshot
  src="telephony-add-number.png"
  alt="The add-phone-number form with the number, country, inbound agent and default caller ID fields"
  caption="Attaching an inbound agent here is what makes the number answer."
  shot="The add-phone-number form filled in: a redacted number, country selected, an inbound workflow chosen from the dropdown, Active on, and default caller ID on."
/>

Two fields decide behaviour:

- **Inbound agent** — the workflow that answers when somebody rings this number.
  Leave it empty and the number is outbound-only.
- **Default caller ID** — whether test and campaign calls show this number as
  the caller.

</Step>

<Step title="Verify the number you are calling">

On a Twilio **trial** account you can only dial numbers you have verified. That
is the destination — your own phone — not the number you just bought.

Add it under [Verified Caller IDs](https://www.twilio.com/console/phone-numbers/verified)
in the Twilio console. On a paid account this step does not apply.

</Step>

<Step title="Place a real call">

Back in the agent, use **Phone Call** in the editor header, or trigger one the
way you did in
[Trigger Calls using API](/getting-started/trigger-calls-from-your-backend).
Decibyl dials out through Twilio, your phone rings, and the agent starts talking.

<Note>
On a trial account Twilio plays its own message before connecting. Press any key
to skip it and go straight to the agent.
</Note>

Inbound works the same way in reverse: someone rings the number, Twilio hands
the call to Decibyl, and the workflow you attached answers it. The full inbound
setup, including carriers that need manual webhook configuration, is in
[Inbound](/integrations/telephony/inbound).

</Step>

</Steps>

## When the call does not go out

<AccordionGroup>

<Accordion title="The Phone Call button is greyed out">
It disables while the agent has unsaved changes or validation errors. Save
first, then check the validation errors in the header.
</Accordion>

<Accordion title="400: Telephony provider not configured for this organization">
No configuration is set as the default for outbound calls. Edit the
configuration and switch that on — see step 3.
</Accordion>

<Accordion title="Twilio rejects the call">
On trial, the destination number has to be verified (step 5). On a paid account,
the usual cause is that the number you are dialling *from* is not one Twilio has
issued to you, or geo permissions for the destination country are not enabled in
the Twilio console.
</Accordion>

<Accordion title="It rings, connects, and there is silence one way">
One-way audio on a phone call is a media path problem at the carrier, not an
agent problem — the same agent will sound fine on a web test. Note the time and
the number and send it to support; the call logs show which leg failed.
</Accordion>

</AccordionGroup>

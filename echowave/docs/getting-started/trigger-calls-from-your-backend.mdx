---
title: "Trigger Calls using API"
description: "Turn a row in your CRM into a personalised phone call, automatically, with one HTTP request."
---

Your leads are already in a CRM, a spreadsheet, or a table in your own database.
Each row has a name, an amount, an account number. This page turns one of those
rows into a phone call the agent has already been briefed on — so it opens with
*"Hi Rushil, I'm calling about your Quick Credit account"* instead of asking who
it is speaking to.

The mechanism is the **API Trigger** node. It gives your agent a URL; you POST a
phone number and a bag of variables to it, and the call goes out.

**Before you start:** a [telephony provider connected](/getting-started/connect-telephony)
for outbound calls, and an [API key](/configurations/api-keys) from the
developer portal.

<Steps>

<Step title="Add the API Trigger node">

Open your agent, click the **+** button on the canvas (*Add node*), and choose
**API Trigger** — it is the first entry in the list.

<Screenshot
  src="api-trigger-add-node.png"
  alt="The add-node menu open on the canvas with API Trigger at the top of the list"
  caption="+ on the canvas, then API Trigger."
  shot="The add-node popover open over the workflow canvas, with API Trigger highlighted at the top of the list. Crop to the popover plus a little canvas around it."
/>

The node has no settings to fill in. Adding it is what creates the endpoint.

</Step>

<Step title="Copy the trigger URL">

Open the node. It shows two URLs, both ending in the same UUID:

| | Runs | Use it |
| --- | --- | --- |
| **Test URL** | Your latest saved draft | While you are still changing the agent |
| **Production URL** | The published version | Once you are live |

<Screenshot
  src="api-trigger-urls.png"
  alt="The API Trigger node panel showing the test and production URLs with copy buttons"
  caption="Two URLs, one UUID. The production one runs the published agent."
  shot="The API Trigger node's settings panel with both URLs visible. Blur or replace the UUID."
/>

<Warning>
The production URL keeps serving the **published** agent. Edit the agent and the
production URL does not change behaviour until you press **Publish** — which is
the point of it, and also the thing people trip over. If a change is not showing
up on a real call, check whether you published.
</Warning>

</Step>

<Step title="Send the request">

POST to the URL with your API key in the `X-API-Key` header. Two fields matter:
`phone_number`, and `initial_context` — a free-form object of variables the
agent can reference in its prompts as `{{initial_context.field}}`.

```bash title="Trigger a call"
curl -X POST https://api.decibyl.ai/api/v1/public/agent/test/{uuid} \
  -H "Content-Type: application/json" \
  -H "X-API-Key: dcb_your_api_key" \
  -d '{
    "phone_number": "+919876543210",
    "initial_context": {
      "debtor_name": "Rushil",
      "client_name": "Quick Credit",
      "debt_amount": "3500"
    }
  }'
```

The keys inside `initial_context` are yours to choose. Whatever you send is what
your prompts can reference — a Start Call greeting of
`Hi {{initial_context.debtor_name}}, this is Alex from {{initial_context.client_name}}`
resolves against exactly these fields.

<Tip>
Send this from Postman first, once, by hand. Getting the shape right against a
tool that shows you the response is much faster than debugging it inside your
CRM's webhook runner.
</Tip>

</Step>

<Step title="Listen to the result">

The call goes out immediately. Because the agent was briefed before it dialled,
the opening line is specific:

> *"Hi, this is Alex from Apex Recovery Solutions. Am I speaking with Rushil?
> I'm calling about your Quick Credit account with an outstanding balance of
> ₹3,500."*

No setup questions, no "can you confirm your account number please". The
recording and transcript appear under **Usage** once the call ends.

</Step>

</Steps>

## Common errors

<AccordionGroup>

<Accordion title="400: Telephony provider not configured for this organization">
No telephony configuration is marked as the default for outbound calls. Open
**Telephony**, edit your configuration, and switch on **Set as default for
outbound calls**. Having a configuration is not enough — one of them has to be
the default. See [Connect with Telephony](/getting-started/connect-telephony).
</Accordion>

<Accordion title="401 or 403">
The `X-API-Key` header is missing, misspelled, or holds a key that has been
archived. Keys start with `dcb_`. Generate a fresh one in the developer portal
and try that.
</Accordion>

<Accordion title="The call connects but the variables come out empty">
Two things to check. First, that the placeholder is spelled
`{{initial_context.debtor_name}}` and not `{{debtor_name}}` — the prefix is part
of the name. Second, that you are hitting the URL for the version you edited: a
prompt changed on the draft is not on the production URL until you publish.
</Accordion>

</AccordionGroup>

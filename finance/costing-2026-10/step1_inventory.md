**How to read "who pays":**
- **Platform-paid (company bill):** the company's own key does the spending. These keys live in an encrypted database store and are seeded from env vars named `PLATFORM_KEY_<COMPONENT>_<PROVIDER>` (`api/services/configuration/platform_credential_seed.py:43`). A customer who picks provider `decibyl` gets a "managed tier". That tier is rewritten to a real vendor and model in `api/services/configuration/managed_tiers.py:250-362` and resolved against the platform key in `api/services/configuration/managed_resolution.py:125`. The company then re-bills the customer at a markup set by `MANAGED_PROVIDER_MARKUP_BPS`.
- **BYOK:** the customer's own key or carrier account is used, so there is no company vendor bill. The only exception is if staff install a platform key for that vendor.
- **Self-hosted:** infra cost only.

## Ambiguities worth checking

1. **The docs no longer match the managed-tier code.** `DEPLOY-ENV.md:52-56` says `PLATFORM_KEY_LLM_GOOGLE` serves the default/lite tiers. The code at `managed_tiers.py:250-256` now uses Sarvam for lite and OpenAI for default/accurate/advanced. Keys the code needs that the doc does not list: `PLATFORM_KEY_LLM_SARVAM`, `PLATFORM_KEY_TTS_ELEVENLABS`, `PLATFORM_KEY_TTS_SMALLEST`, `PLATFORM_KEY_TTS_RUMIK`, and optionally `PLATFORM_KEY_STT_DEEPGRAM`. A Google key is now needed only for Gemini Live, the agent builder and the chat catalogue. Tiers can also be moved by DB overrides or `MANAGED_<COMPONENT>_<TIER>`, so the live vendor list may differ from the defaults.
2. **Who runs MPS (`services.decibyl.ai`) and who pays whom is unclear.** The code uses `pipecat.services.dograh.*` classes (`service_factory.py:60-63`), so this looks like the upstream open-source project's hosted proxy. `REBRAND_HANDOFF.md:15` says the user "does not own these hosts yet". If this is right, the proxy would pay the upstream vendors and bill this company per usage, authenticated by `DECIBYL_MPS_SECRET_KEY`. Today managed tiers are rewritten to direct vendor calls before the pipeline is built, so MPS is only reached on the legacy path (`managed_service_version == 2`), for service keys, and for `KB_DOCUMENT_PROCESSOR=mps/auto`. `app.py:76` warns at boot when `MPS_API_URL` is inherited.
3. **Any vendor can become platform-paid.** Staff can install a platform key for any provider (superadmin provider-keys, or `use_platform_key=True` at `registry.py:215`). That turns any BYOK vendor in rows 11–16 into a company cost.
4. **Managed telephony is probably not live.** `MANAGED_TELEPHONY_ENABLED` defaults to false. `MANAGED_TELEPHONY.md` says the provisioning and rental billing were built later, but whether any org is actually on company-owned Plivo numbers is a production-data question.
5. **Hosting target vs. reality.** `INFRASTRUCTURE.md` describes RDS Multi-AZ, ElastiCache and Route 53 as the target, but the current deployment is one EC2 box with Postgres, Redis and MinIO in containers. Whether S3 or MinIO holds recordings in production depends on `ENABLE_AWS_S3`.
